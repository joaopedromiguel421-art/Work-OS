# Landing page

This Skill is the single integration owner for a landing-page deliverable. It calls companion procedures for their distinct expertise without duplicating their authority.

## Method

1. Confirm traffic source, target segment, awareness level, offer, single primary conversion, qualification, approved claims, and measurement baseline.
2. If the offer is unresolved, invoke `positioning-and-offer`; if evidence is missing, stop and name the gap.
3. Build a message/page hierarchy around the visitor's decision: orientation, value, mechanism, outcomes, proof, fit, objections, risk, and action. Omit sections that add no decision value.
4. Use `copy-and-content` for exact copy and `interface-design` for flow, responsive behavior, states, accessibility, and design-system fit.
5. Specify form fields, validation, consent, privacy notice, success/error behavior, destination, and lead-routing ownership.
6. Use `seo` only when organic discovery is a goal. Use `analytics-measurement` for event/identity/consent semantics.
7. Implement in the main conversation. Verify build, links, forms in a safe test target, accessibility, responsive layout, metadata, performance budgets, and event payload schemas.
8. Use `cro-experimentation` for prioritized post-baseline hypotheses; do not disguise a redesign as a validated experiment.

## Independent critique

`ux-critic` may review a coherent page read-only. The main conversation adjudicates findings and makes all changes.

## Guardrails

No invented proof, deceptive UI, hidden consent, fake urgency, inaccessible forms, or live publication/deploy without human approval.

## Output

Page brief, hierarchy/wireframe description, final copy, state/form specification, proof and claim ledger, SEO/measurement requirements, deterministic results, and launch approval list.
