# SEO workflow

## Entry

- Required: site/scope, market/language, business outcome, current baseline access, and whether work is technical, page, or strategy.

## Main-conversation sequence

1. Read product, architecture, metrics, content, routing, and deployment context.
2. Use `seo` to define intent, page mapping, technical audit dimensions, and evidence priorities.
3. Use `research-scout` for current search-result/competitor branches only when raw external evidence is material; avoid rank claims from one location/session.
4. Run authorized deterministic crawl, link, status, rendering, sitemap, schema, accessibility, build, and performance checks available in the project.
5. Prioritize blocking discoverability/indexing issues before content scale.
6. Use `copy-and-content` for useful page updates and `analytics-measurement` for search/conversion measurement.
7. Implement repository changes in the main conversation; do not publish or modify external search consoles without approval.
8. Re-run affected checks and record a dated baseline and follow-up window.

## Parallelism

Technical repository audit and independent intent/SERP research may run concurrently if they do not share changing state, maximum two. All remediation sequencing remains in main.

## Complete when

Findings cite current evidence; canonical/index/crawl behavior is internally consistent; content maps to distinct intent; required standard gates pass; measurement and follow-up exist; no ranking promise, link scheme, or external account action is made.
