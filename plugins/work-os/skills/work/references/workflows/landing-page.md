# Landing page workflow

## Entry

- Required: audience, traffic source, offer, conversion action, approved claims/proof, brand/design authority, and target environment.
- Resolve: form/lead ownership, privacy/consent, baseline, SEO goal, and launch approval owner.

## Main-conversation sequence

1. Read project/product/brand/users/metrics context and relevant existing page/code.
2. Use `market-intelligence` or `research-scout` only for a material audience/competitor evidence gap.
3. Use `positioning-and-offer` if the offer is not accepted.
4. Invoke `landing-page` as integration owner; it uses `copy-and-content`, `interface-design`, `analytics-measurement`, `seo`, and `cro-experimentation` only for their distinct steps.
5. Create the page brief, hierarchy, copy/claim ledger, interaction/state/form specification, measurement contract, and acceptance criteria.
6. Implement all writes in the main conversation against the existing design system.
7. Run build, link/form schema tests, accessibility, responsive checks, metadata, analytics schema, and performance checks configured by the project.
8. Invoke `ux-critic` for a final coherent-page review and resolve findings in main.

## Parallelism

Early market evidence and baseline analytics may run independently, maximum two read-only branches. UX critique waits for a coherent artifact. Copy and design are dependent and stay integrated in main.

## Complete when

Claims have proof/approval; all states and consent behavior work; standard quality passes; conversion events are QA'd; accessibility/responsive/performance criteria are met; deployment/publication remains pending explicit approval unless already granted.
